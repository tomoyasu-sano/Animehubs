# ループエンジニアリング × Instagram自動化 — 整理ノート

> YouTube動画「ループエンジニアリングでSNSを完全自動化」の内容整理。
> 実装は別Claude（Claude Code想定）に渡す前提で、概念 → 全体設計 → ファイル構造 → 具体仕様 の順にまとめた。
> **重点：Instagram自動化。ただしループエンジニアリングの仕組み自体は全媒体共通なので汎用部分も残している。**

---

## 0. 一言で言うと

「プロンプトを毎回打つ」時代は終わり、**ゴールと検証方法を一度設計しておけばAIが自律的に回り続ける『ループ』を作る**のがこれからのやり方。
このループを使って、1つの一次情報（例：YouTube動画）を起点に各SNS向けコンテンツを自動生成・検証・下書き保存まで回す。**公開（投稿ボタン）だけは人間が押す。**

---

## 1. ループエンジニアリングとは

### 1.1 定義
- ゴールと検証方法を先に設計し、AIが自動で回り続ける「ループ」を作る技術。
- 人間が毎回プロンプトを打つのではなく、**「何を達成したら終わりか」「できたかどうかをどう確かめるか」を先に決めて、あとはAIに任せる**。
- 1回設計すれば、成果物が出続ける。次の指示はループ自身が考え、終わっても自分で再開する。

### 1.2 プロンプト時代との対比
| | プロンプトエンジニアリング（〜2024的） | ループエンジニアリング（これから） |
|---|---|---|
| 指示の出し方 | 毎回、長いプロンプトを人間が考えて投げる | 1回ゴール設計すれば自動で回る |
| 継続性 | 出力が終わると止まる | 終わっても自分で再開・ルーティン化 |
| 次の指示 | 人間が考える | ループが考える |
| 稼働 | 人間が起きてPCの前にいる時だけ | 24時間365日 |

> 動画内の根拠：Claude Code開発者ボリス・チャーニー氏、OpenAIエンジニア（スタインバーガー氏）らも「コーディングエージェントにプロンプトを打つのではなく、指示を出すループを設計すべき」と公言している、という主張。
> ※ 人物名・発言の固有名詞は動画の聞き取りベース。実装ドキュメントに引用する場合は要ファクトチェック。

### 1.3 ループの4ステップ（コア思考サイクル）
これを着実に回せば成功する、とされる中核ロジック。

1. **ゴール（Goal）** — 何を達成したら終わりかを明確化する。
2. **実行（Execute）** — ゴールに向かってタスクを実行する。
3. **検証（Verify）** — できたかを自分で確かめる。
4. **修正（Refine）** — エラー・未達・品質不足を見つけ、修正して ステップ1へ戻る。

検証→修正を何度か回し、**うまくいったパターンをループ機能として固定**することで、放置しても品質が落ちない状態を作る。
（自己検証を入れると成果物の品質が約2〜3倍になる、という主張あり。）

### 1.4 ループでできるようになる3つのこと
1. AIが長時間、壊れずに自走できる。
2. AIが自分の仕事を検証し、品質の低いものをブラッシュアップできる。
3. サブエージェント（AI社員的な並列作業者）を必要な時だけ雇い、終わったら解散できる。

### 1.5 ループを作る4つの道具（Claude Code標準機能）
> ※ 動画内の聞き取りベースの機能名。実際のClaude Codeのコマンド名・仕様は実装時に要確認。

| 道具 | 役割 |
|---|---|
| `/loop`（スラッシュループ） | タスクを回し続ける中核機能 |
| `/goal`（スラッシュゴール） | ゴールを設定し達成まで自律実行 |
| ウルトラ系モード（大量並列） | 多数のエージェントを並列で走らせ、一気に検証・量産 |
| サブエージェント | ループが必要時に自動で雇い、終わったら解散する「部下」 |

### 1.6 「AI社員方式」から「ループ方式」へ
- 従来：AIに役割（ライター係・リサーチ係・編集係）を与えて人間が指示。優秀だが**指示待ち＝人間がボトルネック**。AI社員が増えるほど管理する人間の仕事も増える。
- これから：飼い主が「人間」から「ループ」に変わる。事前設計したものを、ループが覚えて自分で指示・実行する。
- ※ AI社員が消えるわけではない。指示する主体がループになるだけ。

## 2. SNS自動化の全体設計

### 2.1 対象媒体（動画で扱う7媒体）
YouTube / X / ショート動画（TikTok等）/ note記事 / Tips（noteに近い有料記事系）/ Threads / **Instagram**

→ これを1人で全部やるのは現実的に無理。だからループで回す。

### 2.2 基本構造：「一次情報を起点に横展開」
```
[大元の一次情報]  ← 自分が体験・発信した一次情報（例：YouTube動画の文字起こし）
       │
       ▼   ループが各媒体向けに変換・検証・保存
   ┌───┬───┬───┬───┬───┬───────────┐
   X   note  Tips Threads ショート  Instagram(リール)
```
- 起点は「更新コスト高め＆情報量の多い媒体」（YouTube、ブログなど）。
- そこから「更新しやすい媒体」へループで落とし込む。
- **大元の一次情報があるからこそ各媒体が伸びる**（後述の「よくある失敗」と直結）。

### 2.3 ループが各媒体で行う4つの動き
1. 素材から、媒体ごとのコンテンツを生成。
2. フォーマット＆ファクトをチェック・検証。
3. 投稿 or 下書き保存。
4. 結果を記録して次の素材へ。

### 2.4 自動実行の流れ（動画の実例タイムライン）
> 時間はあくまで設計例。

| 時刻 | 動作 |
|---|---|
| 21:00 | ループ起動。今日の動画の文字起こしを取得 |
| +10分 | X記事を生成 → 文字数・URLが有効かを検証 → 保存 |
| +30分 | note記事を執筆（タイトル3案）→ ファクトチェック → 下書き保存 |
| +50分 | Tips記事（約5000字）を執筆 → 投稿 |
| +40分 | ショート台本3本＋Threads連動を生成 |
| 朝 | 起きると「成果物一覧＋数値レポート」が残っている状態 |

### 2.5 人間に残る仕事（＝最重要）
1. **最初のループ設計**（ゴール設計と検証方法の決定）。自動化のレールを引く第一歩。
2. **公開前の最終チェック＆公開ボタン**。媒体によっては人間の承認が必須。規約に沿う設計が必要。ファクトチェックも人間が担うべき場面あり。

## 3. ファイル構造とプロンプト（実装の骨格）

### 3.1 ファイル構造イメージ
```
プロジェクト/
├── CLAUDE.md                  # ループ全体のルール・前提を定義
├── skills/                    # 媒体ごとの「作り方マニュアル＝ルールブック」
│   ├── x投稿の作り方.md
│   ├── note記事の作り方.md
│   ├── tips記事の作り方.md
│   ├── threads投稿の作り方.md
│   └── instagram_リール台本の作り方.md
├── memory/                    # 学習・記録（失敗を二度繰り返さないため）
│   └── （媒体ごとの文体規定・禁止事項・過去のミス記録）
└── output/                    # 生成物の保存先
```

- `CLAUDE.md` に紐づく形で `memory/` と `output/` を配置。
- `memory/` には**媒体ごとの文体規定、禁止事項、「この種の数字はファクトチェック必須」等のルール**を記録。失敗したら memory に記録して同じミスを繰り返さない。
- `/（スラッシュ）+ スキル名` が発動条件。これでループ機能が発動し、磨かれたスキル（ルールブック）に従ってアウトプットを出す。

### 3.2 `/loop` プロンプトの一例（動画より）
```
今日公開したYouTubeの文字起こしを素材に、
X / note / Tips / Threads 向けの投稿を順番に作成して。

- 各媒体は対応するスキル（skills/ 内のルールブック）を必ず使うこと
- 完成したら output/ に保存し、検証チェックリストを通すこと
- 全媒体が終わったら成果物一覧をレポート送って終了
```
→ ここまで仕組みを作れば、あとは `/loop` だけで設定済みの指示が発動し、回り続ける。

### 3.3 良いゴール vs ダメなゴール
- ❌ ダメな例：「センス頑張って」「いい感じにして」 — 抽象度が高すぎ、終わりがなく暴走し、できたか確認できない。
- ✅ 良い例：「note記事を1本、下書き保存まで。3000字以上、タイトル3案、ファクトチェック済み」 — 構造・完了条件が具体的。

### 3.4 検証方法の設計が品質を決める（検証チェックリスト項目）
- 文字数は適切か
- 構成・フォーマット通りか（媒体ごとのバズる型に沿っているか）
- 数字・日付はファクトチェック済みか
- URLは開けるか
- 下書きが本当に保存されているか

> X：最近のトレンド投稿の型／バズる文章構成を組み込む。
> 一次情報（YouTube由来）× バズるフォーマット = 各媒体で伸びる、という設計思想。

## 4. Instagram 自動化の具体仕様（重点）

### 4.1 ループにやらせる範囲
- **企画 → リールの台本 → キャプション** までを生成。
- 企画は基本 YouTube（一次情報）から引っ張る前提。

### 4.2 リール台本で特に重視するポイント
- **冒頭のフック（ボートのフック＝出だしの掴み）が最重要。** バズるかどうかを大きく左右する。
- 構成も重要。
- **「何を書くか」だけでなく「何を書かないか」が同じくらい大事。**
  - ショート動画は基本「暇つぶし」で見られる。
  - だから「いかに簡単そうに見せ、分かりやすく端的に、不要な情報を排除して発信するか」が鍵。
  - （YouTubeは情報を何度も反復してインプットさせる勉強材料 ⇄ ショートは真逆の設計、という対比を理解させる。）
- 検証では「この簡潔化・フック設計がちゃんと効いているか」をチェックし、不足があれば修正させる。

### 4.3 公開の扱い（重要・規約遵守）
- **Instagramは基本「人間が投稿」する。** 自動投稿は凍結・アカウントBANリスクがある。
- ループに任せるのは**生成〜下書き保存まで**。最後の公開ボタンは人間が押す。
- 予約投稿機能を使う／まとめて人間が予約する、なども可。

### 4.4 実績（動画の主張）
- 発信者の自社・代表（奥山氏）のInstagramアカウントは**フォロワー約8.9万人**、ほぼAI（ループ機能）活用で到達したと主張。企画から台本落とし込み、台本チェックまでAIにやらせている。
- ※ 数値・実績は動画の主張ベース。

## 5. 媒体別ループ設計表（Instagram中心・主要媒体）

| 媒体 | ループにやらせるゴール | 検証 | 公開 |
|---|---|---|---|
| **Instagram** | 企画／リール台本（冒頭フック・構成）／キャプション生成 | フック・構成・簡潔化が効いているか／フォーマット | **人間が投稿（自動投稿はBANリスク）** |
| YouTube | 企画・台本・概要欄まで（投稿までの一連を生成） | 字幕同期・誤字・フォーマット | **手動投稿（自動はBANリスク）** |
| X | 投稿文（記事投稿時はサムネも生成可）・トレンド型 | フォーマット・URL | 人間が公開ボタン（下書きまで自動。自動公開は炎上/凍結リスク） |
| note | 記事執筆〜下書き保存（タイトル3案） | ファクトチェック・URL・下書き保存確認 | 人間が公開 |
| Tips | 品質の高い記事を執筆 | フォーマット・ファクト | （noteに準ずる） |
| Threads | 文章生成（X/ショートと連動） | フォーマット | 人間が公開 |

> ※ 各媒体の利用規約は変わりうる。実装時に最新の規約を必ず確認すること（特に自動投稿の可否）。

## 6. よくある失敗（実装時の注意・回避すべきこと）

1. **ゴールが曖昧で暴走する。**
   → 構造を理解し、人間側で具体的なゴールを設計してから走らせる。動画いわく、実は「実践」より「ゴール設計＋検証設計」が一番重要。

2. **検証なしでループ化し、低品質を量産する。**
   → 大元が一次情報（自分の体験・コンテンツ）であり、ファクトチェック済み、各媒体のバズる型で設計されていればコンテンツ質はOK。
   → ネットの記事をAIにまとめさせただけだと「3次・4次情報」になり、どこかで聞いた内容になって誰も見ない。**一次情報が大前提。**

3. **全自動を欲張りすぎて事故る（規約違反・凍結）。**
   → 「自動化すればいい」と思い込むと規約違反でBANされる。規約を無視せず、公開は人間承認制にする。

### 6.1 安全装置（暴走対策）
- ゴールに**上限・回数・使用プランの制約**を明記する。無限ループは事故の元（意図せずトークン/クレジットを大量消費し高額課金になる）。
- 停止方法を知っておく：`Ctrl + C` で即停止。「◯◯になったら止まれ」という停止条件もかける。

## 7. 実装ハンドオフ用チェックリスト（別Claude向け）

このノートを基に実装する際、最低限カバーすべき項目：

- [ ] `CLAUDE.md` にループ全体のルール・前提・安全装置（上限・停止条件）を定義
- [ ] `skills/instagram_リール台本の作り方.md` を作成（フック設計・構成・「何を書かないか」のルールを明記）
- [ ] `memory/` に Instagram の文体規定・禁止事項・ファクトチェック必須項目を定義
- [ ] 一次情報の入力導線を決める（例：YouTube文字起こしの取得方法）
- [ ] 生成 → 検証チェックリスト → `output/` 保存 → レポートの流れを `/loop` プロンプトとして定義
- [ ] **公開は人間承認制**にする（Instagramは下書き/予約まで、最終投稿は人間）
- [ ] 最新の各SNS利用規約を確認（自動投稿の可否）
- [ ] まずは **1媒体・1ループから**。いきなり全SNSをループ化しない

> 動画の最終メッセージ：いきなり全媒体をループ化しないこと。まず1つ（例：YouTube）の設計→検証→修正を固めて良いループにしてから、次の媒体（X、Instagram…）へ展開する。
